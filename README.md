# Material Preview

VRChatアバターまたは衣装全体のマテリアル案を、AS ISと比較して編集するUnity Editor拡張です。

## 使い方

1. HierarchyでScene上のアバター（またはその子）を右クリックし、`Gokoukotori > MaterialPreview > 編集`を選択します。選択オブジェクト自身に対応Rendererがあれば、そのRendererの比較を開始します。RendererがなくMaterialModifier／AOMEがあればその設定の編集モードを開始し、いずれもなければアバター全体の比較を開始します。複数の設定がある場合は編集対象を選択します。`Tools > Gokoukotori > MaterialPreview > 開く`からの指定も可能です。
2. アバター全体、または衣装全体を選択します。衣装は対象ルートを複数指定できます。衣装モードでは指定した衣装だけをAS IS／TO BEに表示し、衣装の大きさに合わせてフレーミングします。
3. 手動指定の場合は「比較を開始」を押します。Scene上のMaterial割り当てと既存のAOME・TTT MaterialModifier設定、MLICの合成結果を反映したAS ISとTO BEを作成します。
4. 左の一覧でマテリアルを選択し、右で編集中の案の値を変更します。左・右ドラッグで回転、ホイール押し込みドラッグで平行移動、ホイール回転で拡大縮小します。操作方法はプレビューのツールチップでも確認できます。各プレビューで操作は同期し、「選択箇所へ」「全体へ」で平行移動をリセットします。
5. 案を追加・複製し、比較チェックで同時表示を切り替えます。TO BEは最大3案を同時表示できます。
6. 保存する案と方式を指定し、保存内容の確認後に検証・保存します。保存後は必要に応じてSceneを手動保存してください。

比較中はアバター・衣装ルートの指定を固定します。対象を変える場合は「比較を終了・対象を変更」を使用します。プレビューの初期化に失敗した場合は「プレビューを復旧」で描画側も再作成します。

中央上部の「表示」で「3D比較」と「プロパティ比較」を切り替えられます。プロパティ比較では、選択マテリアルのAS ISを左（参照専用）、すべてのTO BEを案の順に右へ並べ、シェーダー付属のGUIで表示・編集できます。3D比較のチェック状態や同時表示上限にかかわらず全案を表示し、収まらない列は横スクロールで確認できます。右側にあった編集欄は中央へ移動し、既存の上書き・今回の変更も確認できます。左右は独立してスクロールでき、条件付き表示によって項目の位置が異なる場合があります。表示切り替えでは編集値・案・3Dカメラの状態を保持します。

3D比較の「照明」で、標準・逆光・横光・暗所・強い光・暖色・寒色を切り替えられます。AS ISとすべてのTO BEに同じ照明を適用します。「照明の調整・落ち影確認」を開くと、球のドラッグまたは左右・高さのスライダーで光の方向を変更でき、光の強さ・環境の明るさ・光の色も調整できます。左右0°は正面、±90°は横、±180°は逆光で、カメラの左右回転に追従します。高さは床の水平面を基準にします。球の黄丸は手前、白い輪は背後の光です。手動調整時は「カスタム」と表示します。「光を一周」は光を自動で一周させ、再クリックで停止できます。プロパティ比較へ切り替えた場合も停止します。

「影」でリアルタイムの影を切り替え、「床」「遮蔽物」で落ち影の確認用オブジェクトを表示できます。元RendererのCast Shadows／Receive Shadowsとシェーダー側の影設定に従うため、影を無効にした対象では表示されません。衣装モードでは選択範囲外のアバター本体は影を落としません。照明設定はプレビュー復旧・表示切り替えでも保持し、元Sceneやマテリアルの保存内容には含めません。暗所では直接光と環境光を下げ、発光や明るさの下限を確認できます。Bloomによるにじみ、発光による周囲への間接照明、ワールド固有のLight Probe・反射・ポストエフェクトの再現は対象外です。

保存は選択した案を採用して編集を終了する操作です。成功後は採用案と開始時のAS ISを表示用に保持し、他の案を破棄します。他にも変更した案がある場合は、その案名を示して破棄を確認します。保存をUndoしても破棄した案は復元されず、編集は再開しません。保存内容の確認ダイアログでは、検証・保存を開始する前にキャンセルできます。キャンセル時は保存処理を実行せず、各案を保持します。開始後は途中キャンセルできないため、完了または失敗までお待ちください。保存に失敗した場合は、Material Previewの保存による変更を復元し、各案を保持します。保存対象に変更がなければ保存ボタンは無効です。

案は複数マテリアルの変更をまとめて保持します。同じ元Materialでも適用設定・Prefab由来が異なるスロットは別項目になります。案は一時編集データであり、閉じた後に案を読み戻すプリセット機能はありません。

「既存の上書き」にはPrefab継承階層のMaterial割り当て、Material Variant、AOME、TTT MaterialModifierの設定元と変更前後の値を表示します。後段で同じプロパティが上書きされる設定も表示します。既存の設定を読み込んだだけでは未保存扱いになりません。「今回の変更」は読み込み時点のAS ISからの差分です。リセットはAS ISへ戻す操作であり、既存Overrideを解除する操作ではありません。

## Rendererからのマテリアル編集

Scene上のアバター内にあるMeshRenderer／SkinnedMeshRendererを持つGameObjectを右クリックし、`Gokoukotori > MaterialPreview > Rendererのマテリアルを編集`（または`編集`）を選択します。子や兄弟のRendererを含めず、選択したRendererだけを通常・VRの3D比較に表示します。非表示のRendererはプレビューでも非表示です。EditorOnly、Prefab編集モード、アバター外のオブジェクトは対象外です。

一覧はマテリアルスロット番号付きで表示します。同じMaterialの重複スロットや未割り当てを区別し、AOMEのスロット除外も反映します。Rendererからアバタールートを特定し、ルート配下の別の枝も含めて、そのスロットに適用されるAOME／TTT MaterialModifierを調べます。空の設定も候補に含み、有効な設定が1件なら自動的に既存設定の編集を開始します。複数の設定、または無効な設定だけがある場合は、一覧上部の「編集先」から選択してください。候補は適用順に並び、階層パスとコンポーネント番号、有効状態を表示します。「通常のマテリアル編集」へ明示的に切り替えることもできます。

既存設定の編集では、そのコンポーネントが対象とするすべてのRenderer・スロットに変更が及びます。画面と保存確認で対象数を表示します。選択Rendererだけに変更を保存したい場合は、通常編集のMaterial Variant等を使用してください。編集欄は選択設定の直後、3Dは後続設定も含めた結果です。後段で上書きされるプロパティや、無効な設定の変更は3Dへ反映されません。

別の編集先や通常編集へ切り替える際、未保存の案があれば保存・破棄・キャンセルを確認します。同じ設定内のスロット選択では案を保持します。複数の異なる設定を同時に編集・一括保存する機能ではありません。元データの変更で比較が停止した場合は「比較を開始」で同じRendererを読み込み直せます。既存コンポーネントのInspectorコンテキストメニューからは、従来どおりコンポーネント単位で開けます。

## 既存コンポーネントの編集

MaterialModifier／AOMEを選択してウィンドウを開くか、「選択中の設定を編集」、コンポーネントのコンテキストメニュー「Gokoukotori > MaterialPreview > 編集」を使用します。Scene上のアバター内の設定が対象です。

- 編集欄は選択した設定の適用直後を表示します。差分表示とプロパティ比較の左列は、選択設定の適用直前の「Override元」（前段の上書きを含む）を基準とし、追加編集なしで既存設定の差分を表示します。未保存判定は編集開始時点からの変更で判定します。3D比較は後続のAOME／MaterialModifierも含む結果を表示します。後続で同じ項目が上書きされる場合、選択設定を編集しても3D表示が変わらないことがあります。
- 一つの設定が複数マテリアルを対象にする場合、編集したプロパティはその設定全体に共有します。対象指定と有効状態は変更しません。無効な設定やOverrideが空の設定も、対象マテリアルが解決できれば編集できます。無効な設定は3D比較に適用されません。
- 「既存の上書き」欄の「Overrideを解除」で、その設定から項目を削除して前段の値を継承します。値が同じ明示Overrideも解除できます。「選択設定の編集をすべてリセット」は設定全体を編集開始時点へ戻します。シェーダーGUIの「−」は項目をOverride元の値へ戻し、明示Overrideは保持します。
- 保存先は選択したコンポーネントに固定します。Prefab由来の設定はScene Overrideとして更新し、Prefabアセットへは適用しません。変更は保存まで一時データに保持し、破棄すれば元の設定を維持します。
- 保存前後に期待するMaterial状態とNDMFの結果を比較し、不一致や未対応の編集では保存を中止します。TTTのDecal・Atlasなどの生成処理や、ビルド時のRenderer統合に関する制限は通常の比較と共通です。

## VRでAS ISと全TO BEを比較（オプション）

Windows x64 / Direct3D 11のUnity Editorから、SteamVR対応HMDへ一つの比較空間を表示します。Edit Mode専用です。PC接続したQuest等もSteamVR経由で使用します。Quest単体では実行できません。

1. SteamVRを別途インストールしてHMDを接続し、SteamVRを起動します。VRChat等、ほかのVRアプリは終了してください。
2. Material Previewで通常どおり比較を開始します。
3. 「VRプレビュー（オプション）」を開き、「VRプレビューを使用する」をONにします。初期状態はOFFです。
4. 「必要な依存を導入」を押します。Valve公式リポジトリからOpenVR 1.16.8 Windows x64 DLLを取得し、固定したSHA-256を照合します。ダウンロードにはネット接続が必要です。導入後は通常の起動時に再取得しません。
5. 「VRで全案を比較」を押します。AS ISと全TO BEがラベル付きで並びます。デスクトップの表示チェックや3枚制限にかかわらず、すべての案を同じ空間に配置します。案の追加・削除・名前・マテリアル変更も反映します。

目線の位置と体感スケールを調整するには、「現実の目の高さ (cm)」と「VR空間の目の高さ (cm)」を指定します。どちらも床から目までの高さで、頭頂までの身長ではありません。初期値は両方160cm（倍率1）です。VR空間側は目の高さを手入力するか、「比較中アバターのView Positionから取得」でSDKの基準値を読み込みます。VRChatで拡大・縮小している場合は、その変更後の目の高さを手入力してください。

現実側は手入力のほか、VR開始後の「HMDから現実の目の高さを取得」、またはVRメニューの「More → Measure height」で取得できます。SteamVRの床設定を確認し、立って正面を向いて取得してください。取得は明示的な操作時だけ行い、その後にしゃがんでも基準値を変更しません。HMD中心ではなく左右の目の中心の高さを使います。

体感スケールは「VR空間の目の高さ / 現実の目の高さ」を倍率とし、床を原点に頭・手・両眼の位置へ同じ倍率を適用します。現実160cm／VR空間104cmなら0.65倍で、現実の10cmの移動はVR空間の6.5cmになり、立った目線は104cmになります。現実の床はVR空間の床に対応し、しゃがむ量も同倍率で反映します。HMD固有の視野角は維持し、両眼の間隔による体感スケールを調整します。メニューのサイズと手からの距離、近距離クリッピングも同倍率にします。設定変更時は現在の水平位置・対象との水平距離と手動の高さ移動を保持します。スティック操作速度は変更しません。

設定はウィンドウのシリアライズ状態に保持し、新しいウィンドウでは初期値に戻ります。通常のPC画面の3D比較は従来の投影方法を使用します。

これは目の高さを基準にする体感スケールの調整です。VRChatの腕の長さによる測定、IK・キャリブレーションの内部処理、ミラーの位置や距離までの一致を保証するものではありません。実際の違和感の解消は、同じHMD・VRChatの目の高さ・対象との距離を揃えて確認してください。

|操作|入力|
|---|---|
|移動|左スティック。左Gripを押すと加速。|
|旋回|右スティック左右。頭の位置を中心に連続旋回。|
|高さ|右Grip＋右スティック上下。|
|ラジアルメニューの表示／非表示|左Yまたは右Bを0.5秒長押し。Indexは左右B、Viveは左右Menu。手を離しても表示を保持し、次の長押しで閉じます。|
|メニュー選択・決定|開いた側のスティックを項目の方向へ倒し切ってフリック選択。途中まで倒すとカーソルとハイライトで候補を確認できます。トリガーでも決定でき、Viveは既定でトリガー確定です。「オプション」の「フリック選択」で切り替えます。|
|照明調整|照明、左右・高さ（左右＝方位±180°・上下＝仰角±80°）、光の強さ（0〜5）、環境の明るさ（0〜100%）、光の色（左右＝色相・上下＝彩度）。光の強さ／環境の明るさは上端0%から時計回りの角度で調整します。中央へ戻しても値を保持し、中央＋トリガーで戻ります。|
|影の確認|「影」、オプション → 「床」「遮蔽物」。|
|現実の目の高さを取得・位置を戻す・終了|オプション → 「HMDから現実の目の高さを取得（VR開始後）」「位置リセット」「VRを終了」。Editorの「VRを終了」からも終了できます。|

各ページの上端は「戻る」（ルートでは「閉じる」）です。スティック中央＋トリガーでも一階層戻れます。メニューボタンの長押しで非表示にした場合は現在の階層を保持します。円形の中央、アイコン、選択カーソル、有効／無効表示、プリセットの選択マーカーとPuppetゲージで現在の状態を確認できます。床・遮蔽物・目の高さ取得・位置リセット・VR終了は「オプション」から操作します。メニュー項目と値表示・操作案内は日本語で表示し、照明プリセットと照明調整・VR終了・目の高さ取得の名称をEditorWindowと揃えています。

左右それぞれに同じメニューがあります。開いた手の移動／旋回入力はメニューへ割り当て、閉じた後もスティックとGripを一度離すまで移動を再開しません。両手が同じフレームで照明を書き換えた場合は左手を優先します。トラッキング・入力フォーカスを失うとメニューを閉じて移動を止めます。SteamVRのコントローラーバインド設定からボタンを変更できます。既定バインドはTouch / Quest Touch Plus / Index / Viveです。

SteamVRダッシュボードの操作中も、HMDの追従と背景の比較描画は続けます。別のVRアプリに表示が切り替わった場合は待機し、表示権限が戻ると同じ視点原点から再開します。

照明はデスクトップ比較と共有します。VR空間では光の方位を空間に固定するため、移動・旋回だけで照明方向は変化しません。表示対象の形状とマテリアルの対応範囲は通常の3D比較と同じです。アニメーション・PhysBoneやVRChat本番の完全再現ではありません。全案を両眼に描くため、案の数やアバターの負荷でフレームレートが下がります。初期描画サイズはSteamVR推奨値の縦横比を保持し、長辺2048以下に制限します。両眼を4x MSAA（非対応GPUでは対応サンプル数）で描き、輪郭のジャギーを抑えてから単一サンプルの送信用テクスチャへ解決します。GPU処理時間・VRAM使用量はMSAAなしより増えます。

VR表示中はデスクトップ比較画像の更新を休止し、モデル形状は変更を検出した場合だけ作り直します。案の編集は引き続きVRに反映し、VR終了後はデスクトップ比較の更新を再開します。VR欄には送信要求fps、両眼のCPU描画・送信要求時間、片眼の解像度を表示します。fpsはUnityから画像の送信を要求した頻度で、SteamVRの再投影後の表示fpsではありません。時間には非同期のネイティブ待機・GPU処理時間を含みません。

VR中の定期検査では変更バージョンを確認し、変更がない間はMaterialのJSON化・コンポーネント評価・依存ハッシュ検査を省略します。元データの編集・階層変更・アセット更新・Undoを検出すると完全検証を実行し、保存前にも必ず完全検証を行います。VR表示中は比較ウィンドウの再描画も要求し、準備済みフレームを更新時と描画直前に処理します。両眼の送信後はD3D11の保留コマンドをFlushでGPUへ発行してからSteamVRへ引き渡し、描画スレッドで続けて次のフレームを待機します。

### 依存と保存先

- パッケージ側に専用名前空間のOpenVR C#バインディング、入力JSON、UIと描画処理を同梱します。Valveのライセンスは `Editor/VR/ThirdParty/LICENSE.txt` に含めています。
- ダウンロード先は `Library/MaterialPreview/VR/OpenVR-1.16.8/material_preview_openvr_api.dll`、利用ON/OFFは `Library/MaterialPreview/VR/settings.json` です。DLLはVR開始前にもハッシュ検証します。途中キャンセルや検証不一致では利用しません。
- Unity用SteamVR Plugin、OpenVR XR Plugin、OpenXRの追加導入は不要です。プロジェクトの既存XRパッケージやXR設定を切り替えません。別のUnity XRセッションとの同時使用には対応しません。
- VR機能はAssetsやStreamingAssetsへファイルを作りません。比較空間はメモリ上のPreview Sceneで、終了・ウィンドウを閉じる・コンパイル・Play Mode移行時に破棄します。元Scene、Prefab、Materialを保存しません。従来の「保存」機能の出力先・一時検証フォルダとは別の扱いです。
- 利用をOFFにするとVRを終了します。DLLはLibraryのキャッシュとして残ります。Libraryを削除した場合は設定も初期化され、再度ONにして依存導入が必要です。

HMDの両眼表示、トラッキング遅延、機種ごとのバインド、SteamVRからの復帰、実アバターの負荷は実機で確認してください。Editor自動テストは機器なしで比較配置・描画・入力状態・解放処理を検証します。

## 保存方式

|方式|結果・条件|
|---|---|
|TTT MaterialModifier|アバター配下に新しい設定を作成。対象外Rendererと元マテリアルを共有する場合は拒否します。|
|AO Material Editor|アバター配下に新しい設定を作成。衣装以外の共有スロットを除外します。|
|Direct Material|Assets内の書き込み可能な元.matを更新。他のPrefabやSceneの参照にも影響します。元がVariantの場合は未対応です。|
|Material Variant|指定したAssets内フォルダにVariantを作成し、対象内のRendererスロットへ割り当てます。Shader変更と親でロックされたプロパティ変更は拒否します。|
|既存設定を更新|各マテリアルの「既存の上書き」欄で選択したAOME / TTT MaterialModifierを更新します。今回変更したプロパティのみを更新し、その他の明示設定は維持します。Prefab由来の設定もSceneのOverrideとして保存し、Prefabアセットへは適用しません。|

選択した案の変更分だけを保存します。「既存設定を更新」以外のTTT/AO保存では、新しい設定を追加します。PrefabのMaterial差し替えのみで更新先コンポーネントがない場合はVariant保存等を選択してください。既存設定との競合や対象外スロットへの波及を含め、保存予定結果と保存後のMaterial状態を複製アバターのNDMF処理で検証します。Material状態が不一致の場合は保存を中止し、保存中の変更は復元します。更新先の既存設定が後段で上書きされる場合も、期待するMaterial状態と一致しなければ保存できません。

保存検証が保証するのは、追跡可能なRenderer／スロットのMaterial状態の一致です。Shader・プロパティ値・Texture参照とScale／Offset・Render Queueの実効値・Keyword・GI・Instancing・Tag・Pass状態を照合します（これらすべての編集を保存できる意味ではありません）。数値等は既存の差分判定の許容誤差で比較します。MLICの一時生成画像は参照が異なるため、画像データとサイズ・形式・MipMap等を照合します。その他のTexture画像自体、Mesh・骨・BlendShape等の形状、照明、描画画像および最終的な外観の一致は保証しません。

検証中はAssets直下に専用の一時フォルダを作成し、終了時に削除します。検証が処理中にUnity自体の異常終了で中断された場合、一時フォルダが残る可能性があります。

### 保存成功後のUndo / Redo

UnityのUndo履歴が保持されている間、保存方式ごとに次の範囲を取り消し・やり直しできます。

|保存方式|Undo / Redoの対象|ファイルへの反映・残るもの|
|---|---|---|
|TTT / AOの新規保存|Sceneに追加した設定オブジェクト・コンポーネント|Undo / Redo後にSceneを再保存してください。|
|既存設定の更新・コンポーネント編集|Scene上の設定値・PrefabインスタンスのOverride|Undo / Redo後にSceneを再保存してください。Prefabアセットは変更しません。|
|Direct Material|読み込まれているMaterial値|本ツールはUndo / Redo時に.matを自動保存しません。アセットを再保存すると戻した値がファイルへ反映されます。|
|Material Variant|RendererのMaterial割り当て|生成したVariantアセットは削除しません。Redoは同じVariantへ再割り当てします。Sceneの再保存が必要です。|

Redo前に生成Variantを削除・変更した場合、元のVariantを自動再生成する機能はありません。保存失敗時に行う元ファイルの復元・途中生成アセットの削除は、成功後のUndo / Redoとは別の処理です。

## 対応条件と検証済みバージョン

- Unity 2022.3.22f1
- NDMF 1.14.8以上・2.0.0未満
- TexTransTool（検証済み: 1.1.0-beta.9）
- AO Material Editor（検証済み: 0.1.0-beta.16）

## 現在の対応範囲

- MeshRenderer / SkinnedMeshRendererを対象とし、非アクティブなオブジェクトのマテリアルも一覧に含めます。入れ子の別アバターは除外します。
- MaterialPropertyBlockで表示を上書きするRendererは未対応です。実際と異なる比較結果を表示しないよう、比較開始時・更新時に検出して停止します。
- 編集にはシェーダーパッケージ付属のInspectorを使用します。lilToonのタブ、検索、カテゴリ、プリセット等をそのまま操作できます。編集欄の幅も調整できます。生のプロパティを列挙する独自の汎用表示は廃止しました。
- シェーダー編集画面の変更したプロパティには、AOMEと同じ「−」ボタンを左端に表示します。クリックするとその項目だけ比較元（通常はAS IS、コンポーネント編集時はOverride元）へ戻し、Undoで取り消せます。UnityのMaterialEditorを使用するプロパティ描画が対象で、独自にGUIを描く項目には表示されません。表示処理にはVRC SDK同梱のHarmonyを使用します。
- 標準Inspectorの編集対象はTO BEの一時マテリアルです。通常のMaterial編集では、Material Previewの保存操作まで元Material、Rendererの割り当て、既存コンポーネントを変更しません。専用Inspectorで変更されるShader Keyword、GI、Instancing、タグ、描画パスもプレビューへ反映しますが、これらの差分の保存は未対応のため、変更一覧に表示して保存を拒否します。
- Shader付属GUIはそのまま利用できますが、Shader固有処理によるTexture加工・アセット生成・外部アセットやファイルへの書き込みは、Material Previewの元データ保護の対象外です。副作用の完全な隔離は保証しません。これらの外部変更は案の破棄・リセット・保存失敗時の復元では取り消せず、Undoの可否もShader側の実装に依存します。保護範囲・保存検証・Undoの詳細は、画面下部の「補足・制限」を開くと確認できます（初期状態では折りたたみ）。
- アニメーションによるマテリアル切り替えは対象外です。
- 有効なMLIC（MultiLayerImageCanvas）の合成結果を、通常・VRプレビューとプロパティ比較に表示します。比較開始時に隔離したコピーでTTTのレイヤー合成を評価し、生成画像を各案で共有します。元画像やMLIC設定は変更しません。
- MLICの対象画像を使用するTexture欄は読み取り専用です。Texture参照・Scale・Offset、および対象画像の既存Override解除を禁止し、色や数値などは引き続き編集できます。Shader変更は対象画像のプロパティを維持できる場合に可能です。保存時にも検査し、一時生成画像をMaterialや設定へ保存しません。読み取り専用の範囲はMaterial Preview内です。MLICや入力アセットを外部で変更した場合は比較を開始し直してください。
- MLIC以外のTTTのDecal・Atlas等は生成結果の表示・逆編集に未対応です。該当処理がある場合は警告し、保存結果のMaterial状態の一致を確認できなければ保存を拒否します。既存設定は対応する範囲で取得しており、AS ISはNDMF全ビルド後の外観を保証しません。
- 共有.mat自体を過去に編集した履歴はPrefabから復元できません。Prefabの割り当て差分、Material Variantの親との差分、コンポーネントに現在保存されている上書きが表示対象です。
- Scene上のRendererの形状を直接プレビューします。ビルド時の変形・統合結果はプレビューに含めません。保存時のNDMF評価は維持し、Material状態が一致しない場合やRenderer／スロットを追跡できない場合は保存を拒否します。追跡可能なRendererで形状だけが変わった場合は、この保存検証では検出しません。
- 元マテリアル、割り当て、階層、既存設定の変更を検出した場合は、比較の再開始を要求します。自動で基準を置き換えません。
- ビルドでRendererが統合・削除されたり、参照の異なるTextureが生成された場合など、結果を確認できない保存は拒否します。
- 保存成功後は採用案と開始時のAS ISを表示用に保持して編集を終了します。続ける場合は比較を開始し直してください。
